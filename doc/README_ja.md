# IME トレイアイコン位置ずれ・誤クリック防止 (IME Tray Icon Fix)

Windows 10 / 11 の多言語入力環境において、通知領域（タスクトレイ）にある**入力インジケーター**（IME アイコン）の幅は、入力状態に応じて「1文字幅 ↔ 2文字幅」の間で動的に変化します。通知領域が**右端基準**で配置されているため、この幅の変化によってインジケーターより左側にあるトレイアイコンが一斉に横へずれてしまいます。「**アプリ ウィンドウごとに異なる入力方法を設定する**」を有効にしていると、この状態でトレイアイコンをクリックした瞬間に**狙いとは違う隣のアイコンを押してしまう（誤クリック）**が発生します。

![修正前：トレイアイコンを押した瞬間にインジケーターが縮み、隣のアイコンがずれて誤クリックが発生](before-fix.gif)

---

## 問題：なぜ「誤クリック」が起きるのか

Windows 標準の通知領域の並び順（左から右へ、右端基準）：

```text
  画面左側  <----------------------------------------------------- 画面右端
  [矢印 ^]  |  [トレイアイコン群]  |  [IME インジケーター]  |  [時計]  |  [デスクトップ表示]
```

ご覧のように、**入力インジケーターはちょうど中間に挟まれています**、左にアプリアイコン群、右に時計。「**アプリ ウィンドウごとに異なる入力方式を設定する**」を有効にし、多言語環境（英語 / 日本語 / 中国語など）では、以下の流れで誤クリックが発生します：

1. アプリで文字入力中、インジケーターは **2文字分**（例：`CH` + `中` や `JP` + `あ`）の幅を取っています。
2. トレイアイコン（Steam や Wi-Fi など）をクリックした瞬間、`WM_LBUTTONDOWN`が即座にフォーカスを `explorer.exe` に切り替えます。
3. Windows のシェルは既定の英語状態に戻るため、インジケーターの幅が **1文字分**（`ENG`）へと急に縮みます。
4. 時計が右端に固定されているため、縮んだ分の隙間を埋めようと、**インジケーターより左側にあるすべてのアイコンが右方向へ一斉にずれます**。
5. そして `WM_LBUTTONUP` の判定が下りる頃には、狙っていたアイコンはすでに移動しており、**滑り込んできた隣のアイコンを押してしまう**ことになります。

---

## 解決策

発想はいたって単純です。**入力インジケーターを通知領域の「一番左端」へ追い出す**こと。こうすれば他のアイコンはすべてインジケーターの右側、つまり画面右端から常に一定の距離に並ぶため、インジケーターの幅がどれだけ伸び縮みしても、アプリアイコン群の位置が変化していません。

![修正後：インジケーターが一番左に固定され、右側の全アイコンは右端からの位置を保つため二度とずれない](after-fix.gif)

修正後の並び順：

```text
[IME インジケーター]  |  [矢印 ^]  |  [トレイアイコン群]  |  [時計]  |  [デスクトップ表示]
```

##### タスクバー固定の言語バーの再現？

はい。しかし、この機能は Win10 ですでに壊れており、Win11 で完全に削除されています：

- **Windows 10 で状態が不安定**：さまざまな原因で、言語バーが勝手にオフ（閉じた）状態に戻ってしまいます。
  - **リモート デスクトップ (RDP)**：リモート デスクトップには完全に対応していません。両側でこの設定をオンにしていても、必ず言語バーがオフの状態に戻ります。
- **新入力方式で非対応**：新 Microsoft Pinyin 自体が言語バーの固定に対応しておらず、手動で「以前のバージョンの Microsoft Pinyin を使う」をオンにしない限り使えません。
- **Windows 11 で完全に削除**：依存している DeskBand などのインターフェースが完全に削除されたため、標準の固定機能はもう使えません。

## Windhawk Mod

[Windhawk](https://windhawk.net) はオープンソースの Windows カスタマイズツールです。Mod は `.wh.cpp` ソースファイルとして配布され、Windhawk がコンパイルとプロセスへの注入を担当します。

両 OS では通知領域の内部実装が全然異なります（Windows 10 は命令的で状態を持たない Win32 ウィンドウ再配置、Windows 11 は宣言的 XAML で、依存プロパティを書き換えてフレームワーク側に自動再配置）。そのため、コードを共有しない二つの独立した Mod に分かれています。

| 項目 | Windows 10 | Windows 11 |
| --- | --- | --- |
| ソースファイル | `win10-ime-tray-icon-fix.wh.cpp` | `win11-ime-tray-icon-fix.wh.cpp` |
| 技術基盤 | 純粋な Win32 (HWND / ウィンドウのサブクラス化) | XAML (WinRT) |
| Mod ID | `win10-ime-tray-icon-fix` | `win11-ime-tray-icon-fix` |
| 動作確認済み環境 | 21H2 (Build 19044) | 24H2 LTSC / 26H2 |
| 設定項目 | 下記参照（3 つの動作モード） | なし（Mod のオン/オフのみ） |

### Windows 10 版 Mod

3 種類のモードを用意しており、個別に、または組み合わせて利用できます：

- **モード 1：最左端へ移動（推奨）** - インジケーターを通知領域の最初のスロットに配置します。それまで左にあったものは右に移動し、右側のアイコンは一切動かなくなります。
- **モード 2：幅の固定** - インジケーターが常に固定のピクセル幅を占めるようにします。1文字分なら 36、1文字＋補助アイコンなら 58、0 に指定すると完全非表示。
- **モード 3：補助入力アイコンの非表示** - インジケーター内部の「中/英」や「あ/Ａ」ボタンを非表示にします。

> Windows 10 21H2 でテスト済み。Windows 10 20H2 以降（LTSC 2021、Build 19042-19045 を含む）は同一のバイナリ共通基盤を持つため問題なく動作するはずです。以前のビルド（1903/1909 以前）も理論上は動作するはずですが、未テスト。

### Windows 11 版 Mod

行うことは一つだけ：インジケーターを通知領域の最初のスロットに配置します。**ユーザー設定項目は一切なく**、Mod 本体のトグルスイッチのみで制御されます。

- 幅 / 余白の調整：公式 Mod「Taskbar height and icon size」に委ねられています。
- IME 補助アイコンの非表示：公式 Mod「Taskbar tray system icon tweaks」に委ねられています。

> `SystemTrayFrameGrid` の内部実装は環境により `Grid` または `StackPanel` のいずれかになります。Windows 11 24H2 LTSC（`Grid`）および 26H2（`StackPanel`）で動作確認済みです。他のバージョンでも仕組み自体は同じであり、Windhawk が適切に注入を処理するため、動くはずですが、未テスト。
